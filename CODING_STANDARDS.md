# Правила кода

Читает ревьюер, а не исполнитель. Механическое правило (запрещённый API, форма импорта, место файла) —
это проверка в линтере или `checks`, а не строка здесь. Здесь только то, что требует суждения.

## Гейт и тесты

- **Гейт проходит перед каждым коммитом.** Гейт — `gate check`, он идёт на этой машине: команда — `[publish] gate_command` в `.agents/antagor/antagor.toml`, её и запускают перед коммитом.
  pytest (порог покрытия, контракт `--help` и снапшоты, форма `auth status`), контракты потребителей
  (`tests/contracts/`), список изменённых существующих тестов, сборка wheel и `yd --version` из неё,
  обязательные правила Стандарта. Упавший шаг чинят, а не пропускают. CI гоняет ровно это.
- **TDD.** Каждое изменение поведения идёт с тестом, который без него падает; красный прогон — в отчёте
  исполнителя.
- **Тест не подгоняют под код.** Существующий тест меняется, только когда изменилось требование. Шаг гейта
  `existing tests` перечисляет тесты прошлого релиза, которые изменены или удалены; каждый идёт в отчёт с причиной.
- **Планку ставят другие.** Приёмку пишет dev с пользователем, контракты (`--json`, exit-коды, представления `v1`) —
  потребитель: `tests/contracts/<consumer>/<tool>.yaml` (Стандарт cli-generator, раздел «Consumer contracts»). Свои — unit-тесты и офлайн-данные для `run`-кейсов потребителей (`tests/contracts/fixtures.yaml`).
  Контракт потребителя не правят, чтобы пройти.
- **Мутационное тестирование — время от времени и перед крупным релизом** (не в гейте):
  `uv run --group mutation mutmut run`, затем `mutmut results`. Выживший мутант — строка, которую ни один тест
  по-настоящему не проверяет.
- **Долгая команда — только отвязанной.** Гейт, долгий запуск `yd`:
  `scripts/run_detached.sh <label> <command...>`, затем `scripts/runs_status.sh <label>`. В своей оболочке агента
  она умирает вместе с ходом (прерывание — например, входящее сообщение herdr), и работу делают заново.

## Устройство (не нарушать)

- **Команда тонкая.** `commands/` — только разбор аргументов; вся логика — в `core/`.
- **Внешние API — в `providers/`.** `httpx` вне `providers/` ruff не пропускает (TID251).
  У провайдера есть `name`, `credential_fields`, `required` и `health_check()` — один дешёвый бесплатный вызов
  на чтение. JSON `auth status --check --json` — контракт между инструментами: изменить его — ломающее изменение.
- **Секреты — только keychain и переменные окружения** (`credentials/`), никогда в аргументах,
  в репозитории или в файле проекта.
- **Вывод — через `output/`.** Каждая команда умеет human и `--json` (`output.emit_success` / `output.guard`),
  `print()` ruff не пропускает (T20). stdout — только данные; ошибки, `--verbose` и `logging` — в stderr. Группа команд —
  `output.group("...")`, не `typer.Typer(...)`: так `yd <group>` без подкоманды печатает help.
- **Ошибки — `CliError` со стабильным `code`** и фиксированной таблицей exit-кодов (`core/errors.py`), не голые
  исключения.
- **Необратимое действие снаружи — с `--dry-run`** (`output.is_dry_run`) и за `output.require_confirmation`.
  Команды только над локальными файлами проекта (`init`, `config set`) этого не требуют.

## Контракт `--help`

- **Докстринг команды — её API.** Агенты узнают команды из голого `yd` / `--help`. Изменилось
  поведение команды — меняется её докстринг в том же коммите: строка-резюме, необязательный абзац и строка
  `Example: {cli} <command> ...` (`output.guard` подставляет `yd`); у каждого `typer.Option`/`Argument`
  есть `help=`.
- **Дифф снапшотов — видимое изменение.** После правки: `uv run pytest --snapshot-update` и прочитать дифф
  `tests/snapshots/help/` и `tests/snapshots/describe.json` (`describe --json` — машинный контракт для каталога
  инструментов и платформы).
- **`src/rb_yandex_direct/data/SKILL.md` не перечисляет команды**, только соглашения. Его меняют, только когда
  меняется соглашение (новый exit-код, новое правило про ключи).

## Версии и релизы

- **Версия — git-тег.** В `pyproject.toml` нет `version =` (uv-dynamic-versioning читает последний тег `vX.Y.Z`);
  строку версии нигде не зашивают.
- **Релиз — только через Antagor.** Руками не пушат, не ставят теги и не правят `CHANGELOG.md`;
  force-push и `commit --amend` — никогда.
- **Заметное изменение выходит релизом.** Серверы, другие инструменты и Mac ставят только по тегам, не с `main`.
  Не оставлять влитое без релиза, не назвав причину. Проект может требовать версию через `[cli] min_version`
  в своём конфиге — нужное ему изменение сначала выходит релизом.
- **SemVer — обещание о поверхности CLI.** Убрать/переименовать/изменить команду, флаг, форму `--json`, exit-код
  или код ошибки — ломающее изменение: major, а на `0.x` — minor. Новая возможность при прежнем поведении —
  minor (на `0.x` — patch); исправление — patch. Сначала deprecate (предупреждение), убирать — в следующем
  ломающем релизе.
- **Зависимость от другого нашего инструмента** — совместимый диапазон в `dependencies` (`>=0.2,<0.3`) и
  источник — только реестр Gitea: `[tool.uv.sources] <name> = { index = "gitea" }` (индекс `gitea` с
  `explicit = true` уже в `pyproject.toml`); никогда git-тег, `branch = "main"` и закоммиченный `path =`.
  Подъём — новый релиз зависимости, `uv lock --upgrade-package <name>`, полный гейт, один коммит.

## Внутри системы tools

Инструмент — один сервис из многих: инфраструктура (sysadmin) разворачивает его, держит ключи (секрет-менеджер)
и бэкапит данные (S3).

- **Вопросы и отчёты — Человеку напрямую**: вопрос, варианты, рекомендация. Пока ждёшь ответа, делай то,
  что от него не зависит.
- **Отчёт о релизе** (рядом с тегом): красный прогон новых тестов; каждый изменённый существующий тест с причиной;
  новая или переименованная переменная окружения или ключ; новая локальная база или новый путь к данным; новая или
  убранная зависимость от другого инструмента; обновлённый токен, записанный локально; ломающий релиз. Перед
  ломающим изменением назвать потребителей.
- **В прод агент не ходит.** Ничего не запускать против него: ни `db push` (даже `--dry-run`), ни
  чтение через `*_PROD_DATABASE_URL`, ни ssh на сервер. Нужна проверка в проде — дать Человеку точную
  команду. Локальная одноразовая база (`scripts/pg_test.sh`) — своя.
- **Ничего вне этого репозитория.** Не давать указаний другим агентам и ничего не менять вне него.
  Ошибка или просьба к другому инструменту — Человеку; к инфраструктуре —
  Человеку, для sysadmin.
- **Серверы Linux без экрана.** Сначала переменные окружения, keychain необязателен (без keychain при заданной
  переменной — не ошибка); существующие имена переменных переиспользовать; без TTY никаких вопросов; без путей
  только для Mac.
- **Локальные данные** — в `platformdirs.user_data_dir("<tool>")`, никогда в репозитории; всё состояние — в файле
  базы, миграции запускает сам инструмент; инструмент сам не выгружает и не синхронизирует данные.
